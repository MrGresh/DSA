| Goal | Graph Type | Best Approach | Why / Context Example |
| :--- | :--- | :--- | :--- |
| **Minimum Steps** | **Has Cycles**<br>*(e.g., Grid 4 Directions)* | `BFS` | **Requires unweighted edges (all step costs = 1).** Layer-by-layer traversal guarantees finding the fewest steps first. *(If steps have unequal costs, use `Dijkstra` instead).*<br>📌 *Example: `Minimum Knight Moves`* |
| **Minimum Steps** | **No Cycles**<br>*(e.g., Grid Right/Down)* | `DP` *(or `BFS`)* | Since choices strictly move forward on a DAG, a cell’s optimal answer depends only on downstream states. Solvable in $O(N)$ time with dynamic programming.<br>📌 *Example: `Min Moves Moving Only Down/Right`* |
| **Minimum Cost/Sum** | **No Cycles**<br>*(e.g., Grid Right/Down)* | `DP` | Classical DP table or memoization works because there are no circular dependency loops on a DAG.<br>📌 *Example: `Minimum Path Sum`* |
| **Minimum Cost/Sum** | **Has Cycles**<br>*(e.g., Weighted Graph / Grid 4-Dir)* | `Dijkstra` | **Requires non-negative edge weights.** Standard `BFS` fails because a path with more steps can have lower overall cost. Priority Queue ensures expanding the cheapest cumulative path. *(Use `Bellman-Ford` if negative weights exist).*<br>📌 *Example: `Path With Minimum Effort`* |
| **Maximum Steps** | **No Cycles**<br>*(e.g., Grid Right/Down)* | `DP` | On a DAG, the longest path can be computed linearly in $O(V + E)$ time by taking `Math.max()` during state transitions.<br>📌 *Example: `Longest Increasing Path in a Matrix`* |
| **Maximum Steps** | **Has Cycles**<br>*(e.g., Grid 4 Directions)* | `Backtracking (DFS)` | **NP-Hard (Longest Simple Path Problem).** `DP` fails due to circular dependencies, and greedy searches can loop infinitely. Must explore simple paths with state backtracking. Efficient only for small inputs ($N \le 20$).<br>📌 *Example: `Unique Paths III`* |
| **Maximum Cost/Sum** | **No Cycles**<br>*(e.g., Grid Right/Down)* | `DP` | Identical structure to Minimum Cost on a DAG, but replacing `Math.min()` with `Math.max()`. No risk of infinite loops.<br>📌 *Example: `Cherry Pickup`* |
| **Maximum Cost/Sum** | **Has Cycles**<br>*(e.g., Grid 4-Dir / Positive Weights)* | `Backtracking (DFS)` | **NP-Hard.** `Dijkstra`’s greedy choice property breaks for maximum cost with positive weights because adding edges increases total cost, creating infinite cycles. Must brute-force with backtracking.<br>📌 *Example: `Path with Maximum Gold`* |

### 3 Key Rules of Thumb to Remember

1. **The "Dijkstra Max" Trap:** You can **never** use Dijkstra's algorithm to find a maximum cost path in a graph with positive weights. Dijkstra assumes that once a node is popped from the priority queue, its optimal path is finalized. For a maximum path, a longer winding path could always yield a larger sum, breaking the algorithm.
2. **Cycles = Backtracking for Maximums:** The moment a problem asks for a **maximum** (steps or sum) and allows you to move backwards or in loops, you are looking at a brute-force Backtracking problem. If an interviewer gives you large constraints (e.g., $N = 10^5$) and asks for a maximum, look closely at the rules—the problem *must* restrict movement in a way that eliminates cycles (turning it into a DAG so you can use DP).
3. **DAGs are DP Heaven:** If a graph has **No Cycles**, Dynamic Programming can solve *anything* (Min Steps, Max Steps, Min Cost, Max Cost) in linear time.

# 🚀 Algorithm Strategy: BFS vs. Dynamic Programming (DP)

## 📌 Overview
Choosing between **Breadth-First Search (BFS)** and **Dynamic Programming (DP)** is a frequent decision in technical interviews. Both can find "Minimums," but the structure of the problem dictates the tool.

---

## 🛠️ Decision Matrix

| Feature | BFS (Breadth-First Search) | DP (Dynamic Programming) |
| :--- | :--- | :--- |
| **Primary Goal** | **Shortest Distance / Minimum Steps** | **Optimal Value (Min/Max Sum, Profit, Ways)** |
| **Edge Weights** | All edges must have **Equal Cost (1)** | Edges can have **Different Costs/Weights** |
| **Graph Structure**| Handles **Cycles** (using `visited`) | Requires **DAG** (No Cycles) |
| **Search Style** | **Exploration:** Level-by-level outwards | **Decision-Making:** Sub-problem dependency |
| **Space Complexity**| $O(Width)$ of the graph (Queue) | $O(N)$ or $O(N^2)$ (Memo/Table) |

---

## 🔍 When to Choose BFS
Use BFS when the problem involves **moving through a space** where every move is one unit.

*   **Key Indicator:** "Find the minimum steps/moves to reach X."
*   **Cycles:** If you can move Up/Down/Left/Right or take "Snakes" back to earlier states, BFS is mandatory.
*   **Mechanism:** The first time you hit the target, it is guaranteed to be the shortest path.

### Examples:
1. **LeetCode 909 (Snakes and Ladders):** Cycles due to snakes. Every dice roll = 1 move.
2. **Knight Dialpad / Knight Moves:** Movements can backtrack. Every jump = 1 step.
3. **Shortest Path in 4-Direction Grid:** Moving between cells with equal cost.

---

## 🔍 When to Choose DP
Use DP when the problem involves **optimizing a total value** through a sequence of one-way decisions.

*   **Key Indicator:** "Find the minimum cost/sum," "Max profit," or "Number of ways."
*   **DAG Required:** There must be a clear "forward" direction (e.g., Right/Down only). You cannot have circular dependencies.
*   **Mechanism:** Builds the solution by combining optimal solutions to overlapping sub-problems.

### Examples:
1. **Minimum Path Sum (Grid):** Only "Right" and "Down" moves (No cycles).
2. **Coin Change:** Minimizing total coins for a sum. No cycles (sum only decreases).
3. **Climbing Stairs:** Finding total ways or min cost to reach the top.

---

## ⚠️ Critical Nuances for SDE-1 Interviews

### 1. The "Minimum Steps" Trap
If a problem asks for **Minimum Steps** but has **No Cycles** (e.g., "Min steps to reduce N to 1"), you can use **either**. However, **DP** is often preferred because it avoids the overhead of a Queue and is easier to space-optimize to $O(1)$ or $O(N)$.

### 2. The "Visited" Rule in BFS
*   **Standard BFS:** Always use a `visited` array/set to prevent infinite loops (cycles) and redundant work (re-visiting nodes via different paths).
*   **Tree BFS:** In a binary tree, `visited` is not needed because each node has only one parent (no cycles/multiple paths).

### 3. Handling Different Costs with Cycles
If the problem asks for **Minimum Cost** but there are **Cycles**, BFS and DP both fail. You must use **Dijkstra’s Algorithm** (BFS + Priority Queue).

---

## 💡 Summary Checklist
- [ ] **Can I go backward?** Yes $\to$ **BFS**
- [ ] **Are all moves cost = 1?** No $\to$ **DP** (or Dijkstra)
- [ ] **Is it about counting "Ways"?** Yes $\to$ **DP**
- [ ] **Is it a Tree?** Yes $\to$ **No Visited Array needed**
