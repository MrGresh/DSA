# 🚀 Algorithm Strategy: BFS vs. Dynamic Programming (DP)

## 📌 Overview
Choosing between **Breadth-First Search (BFS)** and **Dynamic Programming (DP)** is a frequent decision in technical interviews. Both can find "Minimums," but the structure of the problem dictates the tool.

---

## 🛠️ Decision Matrix

| Feature | BFS (Breadth-First Search) | DP (Dynamic Programming) |
| :--- | :--- | :--- |
| **Primary Goal** | **Shortest Distance / Minimum Steps** | **Optimal Value (Min/Max Sum, Profit, Ways)** |
| **Edge Weights** | All edges must have **Equal Cost (1)** | Edges can have **Different Costs/Weights** |
| **Graph Structure**| Handles **Cycles** (using `visited`) | Requires **DAG** (No Cycles) |
| **Search Style** | **Exploration:** Level-by-level outwards | **Decision-Making:** Sub-problem dependency |
| **Space Complexity**| $O(Width)$ of the graph (Queue) | $O(N)$ or $O(N^2)$ (Memo/Table) |

---

## 🔍 When to Choose BFS
Use BFS when the problem involves **moving through a space** where every move is one unit.

*   **Key Indicator:** "Find the minimum steps/moves to reach X."
*   **Cycles:** If you can move Up/Down/Left/Right or take "Snakes" back to earlier states, BFS is mandatory.
*   **Mechanism:** The first time you hit the target, it is guaranteed to be the shortest path.

### Examples:
1. **LeetCode 909 (Snakes and Ladders):** Cycles due to snakes. Every dice roll = 1 move.
2. **Knight Dialpad / Knight Moves:** Movements can backtrack. Every jump = 1 step.
3. **Shortest Path in 4-Direction Grid:** Moving between cells with equal cost.

---

## 🔍 When to Choose DP
Use DP when the problem involves **optimizing a total value** through a sequence of one-way decisions.

*   **Key Indicator:** "Find the minimum cost/sum," "Max profit," or "Number of ways."
*   **DAG Required:** There must be a clear "forward" direction (e.g., Right/Down only). You cannot have circular dependencies.
*   **Mechanism:** Builds the solution by combining optimal solutions to overlapping sub-problems.

### Examples:
1. **Minimum Path Sum (Grid):** Only "Right" and "Down" moves (No cycles).
2. **Coin Change:** Minimizing total coins for a sum. No cycles (sum only decreases).
3. **Climbing Stairs:** Finding total ways or min cost to reach the top.

---

## ⚠️ Critical Nuances for SDE-1 Interviews

### 1. The "Minimum Steps" Trap
If a problem asks for **Minimum Steps** but has **No Cycles** (e.g., "Min steps to reduce N to 1"), you can use **either**. However, **DP** is often preferred because it avoids the overhead of a Queue and is easier to space-optimize to $O(1)$ or $O(N)$.

### 2. The "Visited" Rule in BFS
*   **Standard BFS:** Always use a `visited` array/set to prevent infinite loops (cycles) and redundant work (re-visiting nodes via different paths).
*   **Tree BFS:** In a binary tree, `visited` is not needed because each node has only one parent (no cycles/multiple paths).

### 3. Handling Different Costs with Cycles
If the problem asks for **Minimum Cost** but there are **Cycles**, BFS and DP both fail. You must use **Dijkstra’s Algorithm** (BFS + Priority Queue).

---

## 💡 Summary Checklist
- [ ] **Can I go backward?** Yes $\to$ **BFS**
- [ ] **Are all moves cost = 1?** No $\to$ **DP** (or Dijkstra)
- [ ] **Is it about counting "Ways"?** Yes $\to$ **DP**
- [ ] **Is it a Tree?** Yes $\to$ **No Visited Array needed**
